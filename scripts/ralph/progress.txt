## Codebase Patterns
- Keep orchestrator logic in one small Python module (`orchestrator.py`) plus one focused test file (`tests/test_orchestrator.py`).
- Conversation branching is structural: edits to non-tip `<human>` nodes fork by creating `<branch>` nodes, rather than mutating existing history.
- Cancellation is plain-editor-first: set `killed="true"` on `<human>`; do not introduce separate control nodes.
- Backend process never writes conversation XML directly; orchestrator owns canonical rewrite and atomic writes.
